# Armor System

Armor is **class-locked**: each armor piece belongs to one class. This preserves class identity at end-game, keeps PvP readable, and creates distinct loot progression per class. See Classes & Equipment Identity for the locking rule and rationale.

---

## Slots

- **HELMET**, **CHEST**, **GAUNTLETS**, **GREAVES** — canonical armor slots. Gladiators have one item per slot; templates declare compatible slot(s).

---

## What Armor Provides

- **baseStatMods** — template-defined modifiers to the 8 stats (CON, STR, DEX, DEF, SPD, MR, ARC, FTH). These feed into the match-start “effective build” (base + template + instance rolledMods + perks).
- **Defensive profile** — identity is expressed through stat emphasis (e.g. CON/DEF for tanks, MR for mages). Mitigation and HP then follow from Stats & Scaling (effective DEF/MR and CON).
- Armor bonuses should be **impactful but not erase** stat investment or skill-tree identity (Design Constraints & Global Rules).

---

## Template vs Instance

- **EquipmentTemplate** (type ARMOR): slot, class restriction (e.g. `allowedClass: "Tank"`), baseStatMods, rarityRules, ui.
- **Equipment** (instance): templateId, rolledMods (JSON), rarity; owned by a user. Equipped via GladiatorEquippedItem by slot.

At match start the server computes one effective build per gladiator; no mid-match template queries.

---

## Loot and Progression

- Loot drop is 50% armor / 50% weapon (see Loot & Progression Economy). Armor drops are always for the gladiator’s class (or class-agnostic drop resolved to class at open).
- Salvage and crafting (3→1) apply to armor as to weapons; starter gear cannot be crafted or salvaged.
