# Abilities & Spells

Abilities and spells are **template-driven**: behavior is defined in ActionTemplates (and optionally spell-specific config), linked to equipment (e.g. catalysts) or loadouts. Gladiators store only *references* (prepared spell IDs, equipped ability IDs) in their loadout; the runtime resolves behavior from published game data.

---

## Purpose

- **Spells** — mana-cost actions, typically from catalysts (Arcana or Faith). Cast time, cooldown, effect (damage, heal, debuff, zone).
- **Abilities** — class or skill-granted actives/passives. Demo scope is weapon-based combat; class abilities (e.g. 1–2 signature abilities per class) are post-demo. Skill trees grant passives and triggered effects (see Skill Trees).

---

## Spellcasting Equipment (Catalysts)

- **Catalyst** — equipment type that grants spell slots and casting modifiers (e.g. staff, tome, seal).
- Defines: number of spell slots, magic school (Arcana vs Faith), and base stat modifiers (e.g. ARC, FTH, MR).
- Gladiators **prepare** spells by assigning spell IDs to those slots; this is stored in **GladiatorLoadout** (e.g. `preparedSpellIds`).
- Mana pool and mana regen come from stats (MR, ARC, FTH) per Stats & Scaling; catalysts do not override base mana.

---

## Action Model

- Every cast is an **ActionTemplate**: key, name, category (e.g. CAST), cooldownMs, castTimeMs, manaCost, and a behavior payload (hitboxConfig, projectileConfig, damageConfig, effectConfig).
- Equipment links to actions via **EquipmentTemplateAction** (e.g. catalyst → list of spell actions). Prepared spells in loadout reference which of those actions are “slotted.”

---

## Ability Sources (Current vs Planned)

| Source            | Demo scope              | Post-demo / Wiki                    |
|-------------------|-------------------------|-------------------------------------|
| Weapons           | Primary; 4 weapons live | Same; class vs universal scaling    |
| Skill trees       | Stat boosts + some nodes| Full trees: passives, triggers, capstones |
| Class abilities   | Not implemented         | 1–2 signature abilities per class  |
| Catalysts / spells| Optional / partial      | Full prepare-cast loop              |

---

## Design Constraints

- No gameplay logic on-chain; spells and abilities are off-chain definitions.
- Runtime reads **published bundles** (JSON/TS), not live DB template queries.
- Loadout stores references only; behavior lives in static definitions.
